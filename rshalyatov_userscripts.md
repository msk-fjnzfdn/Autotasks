### [ Сценарий 1 — Регистрация пользователя ]

1. Пользователь открывает страницу регистрации и вводит почту пользователя, с которой будет заходить в систему.
2. Пользователь вводит пароль.
3. Пользователь нажимает кнопку «Зарегистрироваться».
4. Если выбранная почта уже существует в системе, система выводит сообщение об ошибке.
5. Если пароль короче 8 символов, система сообщает об этом и просит исправить пароль.
6. Если все данные корректны, система создаёт учётную запись и автоматически открывает сессию пользователя.
7. Система переносит пользователя на страницу «Мои цепочки» и показывает приветственное сообщение.
8. Запускается Сценарий 3 — Создание цепочки задач.

### [ Сценарий 2 — Вход в систему ]

1. Пользователь вводит почту на странице входа.
2. Пользователь вводит пароль.
3. Пользователь нажимает кнопку «Войти».
4. Если пользователь с такой почтой не существует или пароль неверный, система выводит сообщение «Неверная почта или пароль» и предлагает повторить попытку.
5. Если данные верны, система открывает сессию и переносит пользователя на страницу «Мои цепочки».
6. После окончания работы пользователь нажимает кнопку «Выйти».
7. Система завершает сессию пользователя и возвращает его на страницу входа.

### [ Сценарий 3 — Создание цепочки задач ]

1. Пользователь вводит название новой цепочки в форму «Создать цепочку».
2. Пользователь при желании вводит описание цепочки.
3. Пользователь нажимает кнопку «Создать».
4. Если название не заполнено, система подсвечивает поле и просит указать название.
5. Система сохраняет цепочку и добавляет её в список «Мои цепочки» со статусом «активна».
6. Пользователь нажимает кнопку «Открыть» у созданной цепочки.
7. Система открывает страницу цепочки с пустым списком блоков и редактором расписания.
8. Запускается Сценарий 4 — Добавление блока в цепочку.

### [ Сценарий 4 — Добавление блока в цепочку ]

1. Пользователь выбирает тип блока из выпадающего списка каталога блоков.
2. Система показывает описание выбранного блока и поля для его параметров.
3. Пользователь вводит название блока.
4. Пользователь заполняет параметры блока, например URL и метод HTTP-запроса.
5. Пользователь нажимает кнопку «Добавить блок».
6. Если обязательные параметры не заполнены или указан некорректный тип блока, система выводит сообщение об ошибке и не добавляет блок.
7. Система добавляет блок в конец цепочки и отображает его вместе с параметрами.
8. Если блок больше не нужен, пользователь нажимает кнопку «✕» у блока, подтверждает удаление, и система удаляет блок из цепочки.

### [ Сценарий 5 — Тестовый запуск блока ]

1. Пользователь нажимает кнопку «Тест» у нужного блока.
2. Система выполняет блок изолированно, без результатов предыдущих блоков цепочки.
3. Система показывает результат выполнения блока в раскрывающемся разделе «Результат теста».
4. Если блок завершается с ошибкой, например недоступен указанный URL, система выводит текст ошибки в сообщении возле блока.
5. Пользователь исправляет параметры блока в соответствии с текстом ошибки.
6. Пользователь повторно нажимает кнопку «Тест», чтобы убедиться, что блок работает.
7. Система обновляет результат теста при каждом повторном запуске.

### [ Сценарий 6 — Ручной запуск цепочки с промежуточными результатами ]

1. Пользователь нажимает кнопку «Запустить цепочку» на странице цепочки.
2. Система создаёт запись запуска и начинает выполнение блоков в порядке их следования.
3. Система последовательно отображает статус каждого блока: «ожидает», «выполняется», «готово» или «ошибка».
4. Для каждого завершённого блока система показывает его выходные данные в секции «Выполнение».
5. Если какой-либо блок завершается с ошибкой, система подсвечивает этот блок красным, останавливает выполнение цепочки и присваивает запуску статус failed.
6. Система сохраняет запись запуска со всеми логами и обновляет историю запусков.
7. Если цепочка неактивна, система сообщает об этом и не запускает выполнение.
8. Пользователь просматривает промежуточные результаты, чтобы понять, какие данные передаются между блоками.

### [ Сценарий 7 — Просмотр истории запусков ]

1. Пользователь открывает страницу нужной цепочки.
2. Система загружает последние 50 запусков этой цепочки.
3. Система отображает список запусков со статусом и датой каждого запуска
4. Пользователь выбирает интересующий его запуск.
5. Система показывает логи выбранного запуска: время, уровень и сообщение каждой записи.
6. Если запусков ещё не было, система выводит сообщение «Пока пусто».
7. Пользователь возвращается к редактированию цепочки или запускает её повторно.

### [ Сценарий 8 — Настройка расписания автозапуска ]

1. Пользователь выбирает режим расписания: «Каждые N минут», «Ежедневно в HH:MM», «По дням недели» или «Свой cron».
2. Пользователь указывает значения расписания, например интервал 5 минут или время 09:00.
3. Пользователь нажимает кнопку «Сохранить таймер».
4. Система проверяет корректность полученного cron-выражения.
5. Если выражение некорректно, система выводит сообщение об ошибке и не сохраняет расписание.
6. Если выражение корректно, система сохраняет расписание и показывает его в виде понятной подписи, например «Каждые 5 минут».
7. Система активирует планировщик, и цепочка запускается автоматически по расписанию, а каждый автозапуск фиксируется в истории с пометкой «Запуск по расписанию».
8. Пользователь может очистить расписание, чтобы цепочка запускалась только вручную.

### [ Сценарий 9 — Включение и выключение цепочки ]

1. Пользователь находит нужную цепочку в списке «Мои цепочки».
2. Пользователь нажимает переключатель активности цепочки.
3. Система отправляет запрос на смену статуса и обновляет тумблер и бейдж «активна» или «выключена».
4. Система приглушает название неактивной цепочки, чтобы её статус читался с первого взгляда.
5. Пока цепочка неактивна, планировщик пропускает её автозапуски, а при попытке ручного запуска система сообщает «Цепочка неактивна».
6. Пользователь снова нажимает переключатель, чтобы включить цепочку.
7. Система восстанавливает активный статус, и автозапуски возобновляются в течение минуты.
8. Если запрос на смену статуса завершается ошибкой, система выводит сообщение об ошибке и оставляет статус цепочки прежним.
